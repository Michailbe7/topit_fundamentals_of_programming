## Контрольный вопрос

**Почему байткод CPython нельзя считать машинным кодом процессора?**

Байткод — это команды для виртуальной машины CPython, а не для процессора. Процессор их не выполняет, их по одной читает и выполняет интерпретатор. Машинный код привязан к конкретному процессору, а байткод не зависит от компьютера.

# Задание 2. Имена, объекты и сравнение

Результат: `a == b` True, `a is b` True, `a == c` True, `a is c` False. Типы у всех трёх имён `int`, `id(a)` и `id(b)` одинаковые, `id(c)` другой. Прогноз совпал.

![Скриншот 9](images/image9.png)

## 1. Схема имён и объектов

```text
a ──┐
    ├──► [ int 1000 ]
b ──┘

c ────► [ int 1000 ]   (другой объект)
```

## 2. Равенство значений и идентичность объектов

`==` проверяет, что значения равны. `is` проверяет, что это один и тот же объект. `a == c` истинно, так как значения одинаковые, а `a is c` ложно, потому что `int("1000")` создал новый объект.

## 4. Фрагмент со строками

![Скриншот 12](images/image12.png)

Результат: `first == second` → `True`, `first is second` → `True`.

![Скриншот 13](images/image13.png)

Объяснение: `"py" + "thon"` склеивается ещё при компиляции, поэтому `second` оказывается тем же объектом, что и `first`. Если склеить строку во время выполнения (`prefix + "thon"`), то `==` даёт `True`, а `is` даёт `False`. Это деталь реализации CPython.

## 5. Правило

Значения (числа, строки) сравнивают через `==`. Через `is` проверяют, что это один и тот же объект.

## Контрольные вопросы

1.  **Создаёт ли** `b = a` **копию объекта?** Нет. Имя `b` просто связывается с тем же объектом.
2.  **Что возвращают** `type()` **и** `id()`**?** `type()` возвращает тип объекта, `id()` возвращает целое число, которое однозначно определяет объект.
3.  **Почему** `None` **сравнивают через** `is`**, а числа и строки через** `==`**?** `None` существует в одном экземпляре, поэтому достаточно проверить идентичность. У чисел и строк важно значение, а не то, один ли это объект.

![Скриншот 22](images/image22.png)

## Контрольные вопросы

1.  **Почему** `len(symbol)` **и** `len(symbol.encode("utf-8"))` **могут различаться?** `len(symbol)` считает символы, а `len` от байтов считает байты. В UTF-8 русская буква занимает 2 байта, поэтому для `Я` получилось 1 и 2.
2.  **Что означают границы и шаг в** `text[start:stop:step]`**?** Срез берёт символы от `start` включительно до `stop` не включая, с шагом `step`. Отрицательный шаг идёт с конца, `[::-1]` разворачивает строку.
3.  **Почему строка считается неизменяемой, хотя** `.upper()` **возвращает изменённый текст?** Метод не меняет исходную строку, а создаёт и возвращает новую.

**Ошибка**

- Ошибка: TypeError: 'str' object does not support item assignment («объект типа str не поддерживает присваивание по индексу»).
- Причина: строки в Python неизменяемые, изменить отдельный символ в существующей строке нельзя. Чтобы получить другую строку, нужно создать новую, например "а" + student\[1:\].

**3. Путь программы**

Исходный файл → разбор исходного текста → AST → компиляция в байткод → выполнение виртуальной машиной CPython.

**4. Почему результат** `input()` **нужно преобразовывать**

`input()` всегда возвращает строку (`str`), даже если введены цифры. С такими значениями арифметика работает неправильно: `"8" * 2` даст `"88"`, а `"8" * "12.5"` вызовет ошибку. Поэтому значения нужно явно переводить через `int()` и `float()`.
